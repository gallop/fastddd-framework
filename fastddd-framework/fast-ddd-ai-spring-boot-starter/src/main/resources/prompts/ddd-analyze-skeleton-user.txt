## 基础设施表排除规则
以下认证/权限基础设施表由框架模板套件提供，**不要在本次设计中生成**：
- 用户认证表（user / sys_user）：包含 username、password、status 等认证字段
- 角色表（role / sys_role）：包含 role_code、role_name 等
- 权限表（permission / sys_permission）：包含 permission_code 等
- 用户角色关联表（user_role / sys_user_role）
- 角色权限关联表（role_permission / sys_role_permission）

如果业务需要用户扩展信息（如用户资料、积分、地址），请设计独立的扩展表
（如 user_profile、user_point、user_address），通过 user_id 关联到框架提供的用户表。

请按照系统提示中的JSON格式输出你的设计方案，但有以下重要区别：

**不需要为每个表设计详细字段。每个 table 对象的 fields 设为空数组 []。**

你只需要输出：
1. summary - 设计决策总结
2. boundedContexts - 限界上下文列表
3. contextRelationships - 限界上下文间关系（from, to, pattern, description；可选，识别得出才输出）
4. tables - 每张表的元信息：
   - tableName（snake_case，如 order_item）
   - comment（中文注释）
   - aggregateName（所属聚合名）
   - dddRole（AGGREGATE_ROOT / ENTITY / VALUE_OBJECT）
   - domainModelType（RICH / ANEMIC）
   - reasoning（设计推理过程）
   - fields：设为空数组 []
5. relations - 表之间的所有关系（fromTable, toTable, relationType, foreignKeyColumn, comment）
6. aggregates - 聚合分组（aggregateName, rootTable, memberTables, description, contexts〔可选〕）

稍后会逐表请求详细字段定义。请确保表之间的关系和聚合设计完整准确，这是后续字段生成的基础。
